# gtm-engine

Builds the company's core GTM system from positioning through messaging, SEO/GEO, pipeline, and CAC diagnosis.

OpenClaw should use this sequence as a staged spawn workflow.

## Entrypoint
- co-founder

## Steps
1. customer-hypothesis
2. positioning-writer
3. messaging-architect
4. pricing-model-framer
5. landing-page-copywriter
6. pipeline-reviewer
7. seo-geo-strategist
8. cac-diagnostician
9. compound

## Primary outputs
- customer-profile.md
- positioning.md
- messaging-architecture.md
- pricing-model.md
- landing-page-copy.md
- pipeline-review.md
- seo-geo-plan.md
- cac-diagnosis.md
- docs/founder-learnings/

## Human-facing response (required)
Before or alongside any file updates, give the founder a short chat answer first:
- **Bottom line:** the direct verdict or useful answer in 1-2 sentences
- **Do this now:** the single next action plus up to 3 concrete steps
- **Details saved:** list only the artifact paths you created or updated
Keep the chat response under 150 words unless the founder asks for detail. Do not paste full markdown artifacts into chat; files are the durable record for agents.

## Success signals
- founder_has_one_clear_message_and_channel_system

## Operating notes
# gtm-engine

Use this when GTM is the bottleneck.

Flow:
1. tighten customer clarity
2. sharpen positioning and core message
3. turn the message into an offer and landing page
4. assess pipeline quality and discoverability
5. diagnose paid efficiency before adding more spend
6. Capture the learning with compound so the next cycle starts smarter

The system should leave the founder with one message architecture and a prioritized channel plan.
